# BIT 重开模拟器 · 北理工重开模拟器

《BIT 重开模拟器》（北理工重开模拟器）是一款以《人生重开模拟器》为原型打造的北京理工大学特供版文字向小游戏。玩家可以体验一名北理本科生从入学到大四毕业的完整四年：带着开局天赋与自选的属性分配，在一个个月度里经历军训、期末、寒暑假、实习与毕业答辩，碰上选课、竞赛、组队、恋爱、入党、社团任职；大量取材于北理校园生活的事件、重开也不重样的走向、跨局累积的成就与逐月文字回顾，最终把你带到属于自己的那个结局

> 基于《人生重开模拟器》改编的**北京理工大学特供版**文字游戏：抽天赋、分属性，用 48 个回合走完本科四年。
> 软件工程小学期课程作业 · Python 3.12 + pygame 2.6.1 · Windows 单机 · 仅借鉴玩法结构，**文案与数据全部原创**

## 二、玩法介绍

**一句话**：抽天赋 → 分配属性 → 每月触发一条事件 → 四年后按属性与经历判定结局。

### 一局的流程

1. **首页** → 开始游戏
2. **开局页**：系统随机分配书院（睿信 / 求是 / 明德 / 特立）→ 从随机抽出的 **5 个天赋里最多选 2 个** → 把 **20 点**分给智力 / 体质 / 颜值 / 家境（每项上限 10，可点「随机分配」，也可以一点不点直接开始）
3. **每月一个回合**：按时段与条件筛出候选事件 → 按权重随机抽 1 条 → 显示文案与属性变化
4. **第 13 回合（大二 9 月）**：系统在本书院范围内随机分配专业；同一回合还有机会触发「留任部长」
5. **第 48 回合（大四 8 月）**：判定结局并给出升学院校

### 操作

| 阶段 | 操作 |
| --- | --- |
| 抽天赋 | 从随机抽出的 5 个天赋里最多点选 2 个 |
| 分配属性 | 每行的 `-` / `+` 把 20 点分给 4 项属性（每项上限 10），点「开始」 |
| 游戏中 | 点「继续」或按空格 / 回车推进一个月；「自动」开启自动推进；速度按钮切换 1 / 2 / 4 秒；ESC 暂停 |
| 结局 | 点「回顾本局」/「返回首页」/「再来一局」 |

### 六大系统

| 系统 | 要点 | 规模 |
| --- | --- | --- |
| 属性 | 智力 / 体质 / 颜值 / 家境；开局 20 点自由分配，之后只由事件与天赋驱动；0.1 粒度、不封顶 | 4 项 |
| 天赋 | 蓝 75% / 紫 20% / 金 5% 三档；分「属性加成」与「特殊效果」（指定书院、事件加权、强制事件、回溯、判定加成、开局状态） | 27 条 |
| 事件 | 类型分「基础」101 条 / 「特殊」93 条；时段分「常规」109 条 / 特殊时段 86 条（军训、期末、寒假、暑假、实习、答辩）；支持属性与状态门槛、固定回合、概率、多档判定、纯出分、旅游记录等 | 194 条 |
| 结局 | 升学 5 / 就业 4 / 学业 1 / 兜底 1；**硬门槛 + 加权竞争**抽签；升学类另按能力分定院校（16 所） | 11 条 |
| 成就 | 八类判定（结局 / 事件 / 属性 / 排名 / 数值 / 全局 / 状态 / 开局），跨局累计 | 19 条 |
| 回顾 | 最近 5 局的逐月文本与结局，可导出 txt | — |

**结局怎么判**：延毕优先 → 硬门槛过滤（属性 / 标签次数 / 平均综测排名 / 状态）→ 升学类内部按竞争权重抽 1 条 → 再与就业类候选抽 1 条 → 都不满足则「待业」兜底。详见 `docs/02-游戏设计.md` §7。

## 四、下载与运行

### 普通玩家：下载即玩（推荐）

**到发布页下载最新压缩包** → [**Releases（发布页）**](https://github.com/FlySkyXing/Re-BIT/releases)

1. 下载 `BIT重开模拟器v0.5.zip`
2. **先新建一个空文件夹，再解压进去**（包内是 exe 与资源目录，直接解压到桌面会散落一地）
3. 双击 `BIT重开模拟器.exe` 开始游戏

需要 **64 位 Windows**；**无需安装 Python 或 pygame**（运行环境已打进包内）。存档 `save\records.json` 与导出 `exports\` 就在 exe 同目录，删掉即重置。

### 从源码运行

    pip install -r requirements.txt
    python main.py        （在仓库根目录执行）

### 自己打包 exe（Windows）

需要 **PyInstaller**（**仅构建时需要**，运行游戏不需要）：

    python -m pip install pyinstaller
    python -m PyInstaller --noconfirm --clean --onedir --noconsole --name "BIT重开模拟器" main.py

打包后把 `data/`、`fonts/`、`audio/` 复制到 exe 同目录，并新建空白 `save/records.json` 与 `exports/`；交付时压缩整个 `dist/BIT重开模拟器/` 目录即可。

> 为什么用 `--onedir` 而不是 `--onefile`：`--onefile` 每次启动都要把内容解压到临时目录（启动慢几秒、容易被杀软误报），且资源内置后代码必须改成从 `sys._MEIPASS` 读路径；`--onedir` + 资源外置则**完全不用改代码**。

    Re-BIT/
    ├─ main.py                界面层：八个界面 + 绘制 + 输入（785 行）
    ├─ game/                  逻辑层（不依赖 pygame，8 个模块 524 行）
    │  ├─ data.py             读四份 JSON、书院与专业名单、分专业
    │  ├─ player.py           新建玩家、应用天赋、汇总加成
    │  ├─ timeline.py         回合 → 年月、时段判定
    │  ├─ events.py           事件筛选抽取、判定与效果应用
    │  ├─ endings.py          结局判定、升学院校、综测百分位
    │  ├─ achievements.py     成就判定（八类）
    │  └─ records.py          近 5 局记录与成就进度的读写、txt 导出
    ├─ data/                  全部文案与规则参数：talents / events / endings / achievements
    ├─ save/records.json      存档：近 5 局 + 成就进度 + 走过省份（跨次运行保留）
    ├─ exports/               导出的 txt 记录
    ├─ fonts/  audio/         像素字体 Zpix（OFL）/ 按钮点击音效
    ├─ docs/                  设计文档 01~05 + 《项目文档》 + list/ 清单 + test/ 测试报告
    ├─ images/                文档用图（5 张流程图 + 8 张运行截图）
    ├─ prototype/             早期原型（对照用，不是正式版）
    ├─ archive/               历史文档快照（按日期）
    ├─ dist/  build/  *.spec  打包产物与构建缓存（已在 .gitignore 中）
    └─ AGENTS.md  CHANGELOG.md  requirements.txt  todo.md

**分层与依赖规则**：`main.py`（界面）→ `game/*`（逻辑）→ `data/*.json`（数据），**依赖单向**；`game/` 内各模块互不导入，也不出现 pygame，因此逻辑层可在无图形环境下单独检查；**文件读写只发生在 `game/data.py`（读文案）与 `game/records.py`（存档 / 导出）两处**。

## 七、AI 使用说明

本项目是**「人类定设计 + AI 写实现」**的协作产物：设计决策、内容取舍与验收由人类裁定，代码、文案、数值标定与文档由 AI 代理起草，人类逐轮 review 后提交。

### 分工

| 环节 | 人类 | AI 代理 |
| --- | --- | --- |
| 需求与设计裁定 | 提出需求、在多个方案中拍板（技术栈、玩法规则、界面布局、数据结构） | 先检索成熟参考（附来源链接）并给出取舍对比，再按裁定实现 |
| 代码 | 确认方案、试玩验收、提交 git | 编写 `main.py` 与 `game/*`（共 1309 行），保持「入门级最简」风格 |
| 文案与数值 | 确定目标分布与内容要求、决定增删 | 撰写 194 条事件、27 条天赋、11 条结局、19 条成就，并按要求反复标定参数 |
| 测试 | 指定测试口径与验收目标 | 用临时驱动脚本做全量测试（100 局 / 300 局 / 1000 局快速仿真），产出 `docs/test/` 报告并据此调参 |
| 文档 | 审核、提出结构整合要求、确认修订 | 撰写与维护 `docs/` 与 `CHANGELOG.md`，随代码同步 |
| 演示物料 | 演示视频、汇报 PPT | 提供截图清单与图文素材（视频与 PPT 未代做） |

### 约束方式

- 仓库根目录的 **`AGENTS.md` 是给 AI 的硬约束**，共九条：最简原则（不做多余设计与防御性编码）、先检索后设计（必须给可点击来源）、技术栈固定（未经询问不得引入其它依赖或工具）、指令不清晰必须先问（每次给 2~3 个可选项）、只做人类要求的事、设计阶段不写代码、文档只保留五项基础规范、每轮改动记入 `CHANGELOG.md`、代码按 Python 入门级风格写。
- **该文件由人类维护**：AI 不得自行修改，需要修订时先提方案、经人类确认后才写入。
- 每一轮 AI 改动都在 `CHANGELOG.md`「未发布」段留痕（做了什么、为什么、对应哪些文件、如何验证），可逐条追溯。

### 怎么复核 AI 的产出

1. **看 `CHANGELOG.md`**：每轮任务的背景、改动清单、验证方式与遗留问题；
2. **跑测试**：`docs/test/test_7.md` 记录了 300 局全量测试的口径与结果，固定种子可复现；
3. **看《项目文档》**：关键代码、流程图、效果结论与完成度自我评价集中在一份文档里；
4. **数据与代码分离**：所有文案与数值都在 `data/*.json`，复核内容不必读代码。
