## 1. 架构目标与约束

| 目标 | 说明 |
| --- | --- |
| 结构最简 | 只用 Python + pygame，不引入框架、不做分层架构、不写类 |
| 界面与逻辑分离 | 界面只管画与收输入，逻辑不依赖 pygame，便于单独检查 |
| 改文案不用改代码 | 文案与规则参数全部放在数据文件里 |
| 单机运行 | 无网络、无数据库 |

## 4. 模块划分与职责

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `main.py` | 六个界面的绘制与输入、自动推进计时 | 不判断玩法规则、不直接读写文件 |
| `game/data.py` | 读四份 JSON 文案、书院与专业名单、分专业 | 不做界面 |
| `game/player.py` | 新建玩家、应用天赋、汇总抽事件加成 | 不读文件 |
| `game/timeline.py` | 回合→年月、时段判定 | 不做界面 |
| `game/events.py` | 事件条件判断、筛选抽取、应用属性变化与标签 | 不做界面 |
| `game/endings.py` | 结局算分与选取 | 不做界面 |
| `game/achievements.py` | 成就达成判定（结局 / 特殊事件 / 属性值） | 不做界面、不写文件 |
| `game/records.py` | 近 5 局记录的读写、成就进度读写、txt 导出 | 不做界面、不判断玩法 |
| `data/*.json` | 天赋、事件、结局、成就的全部文案与规则参数 | 不含任何代码 |
| `save/records.json` | 最近 5 局记录与成就进度 | 不是文案 |

## 5. 分层与依赖规则

- 依赖方向单向：**`main.py` → `game/*` → 数据与存档文件**，不允许反向依赖。
- `game/` 内各模块之间不互相导入；数据由 `main.py` 读好后作为参数传入。
- `game/` 内不出现 pygame，保证可在无图形环境下检查玩法。
- **文件读写只在 `game/data.py`（读文案）与 `game/records.py`（读写存档、导出 txt）中发生**。
- 文案与规则参数只写在 `data/*.json`，代码里不硬编码文案。

## 6. 数据流

    玩家操作（鼠标 / 键盘 / 自动计时）
        ↓
    main.py：取当前回合 → 调用 game.timeline 判定时段
        ↓
    game.events：筛候选事件 → 随机抽 1 条 → 应用属性变化与标签
        ↓
    game.achievements：检查「触发特殊事件 / 属性达标」成就
        ↓
    main.py：显示事件文案与属性变化
        ↓
    第 48 回合：game.endings 算分 → game.achievements 检查「达成结局」成就
        ↓
    game.records：把本局写入 save/records.json（只保留最近 5 局）
        ↓
    main.py：显示结局页；「回顾本局」读记录；回顾页可导出 txt 到 exports/
