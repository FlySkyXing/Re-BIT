## 3. 真的是 11 条结局在竞争吗 —— 支配关系

### 3.1 结构性支配（代数上恒成立，与随机无关）

| 支配方 | 被支配方 | 得分差 | 说明 |
| --- | --- | --- | --- |
| 保研外校 | 保研本校 | `智力 + 保研` | 智力、标签次数均 ≥ 0 → **保研本校在两者同门槛时永远不可能夺冠** |
| 考研外校 | 考研本校 | `0.5 × 智力` | 同上 |
| 出国留学 | 待业 | `3×家境 + 3×智力 + 0.5×体质` | 待业得分恒 ≤ 0，出国留学恒 ≥ 0 |
| 出国留学 | 延毕 | `3×家境 + 4.5×智力 + 体质` | 同上 |
| 出国留学 | 援建乡村 | `4×家境 + 智力 − 2×学生组织` | 学生组织单局上限 3（见 §6），故恒 > 0 |

### 3.2 实测支配（1000/1000 局恒成立的对）

- **出国留学 恒 ≥** 创业、进入编制、援建乡村、待业、延毕
- **保研外校 恒 ≥** 保研本校、考研外校、考研本校、进入编制、援建乡村、待业、延毕
- 进入大厂 恒 ≥ 援建乡村、待业、延毕；创业 / 进入编制 / 援建乡村 / 待业 之间也是全序压制

### 3.3 结论

**结局表实际上不是 11 选 1，而是「出国留学 vs 保研外校」的二人赛**：

- 两条合计命中 **100%**（56.6% / 43.4%）
- 其余 9 条要么被代数恒等式锁死（保研本校、考研本校、待业、延毕、援建乡村），要么理论上存在窗口但实测最接近一次仍差 3.4 ~ 16.6 分（考研外校、进入大厂、创业、进入编制）
- **根因不是随机性，而是权重表本身**：只有这两条的权重「系数大 + 无标签硬要求」，能直接吃满属性增长

## 6. 两个数据缺口

### 6.1 「进编制」标签没有任何事件提供

- `data/endings.json` 里 2 条结局引用它：进入编制（×2）、创业（×−1）
- `data/events.json` **181 条事件中带该标签的：0 条**
- 实测 1000 局中该标签出现 **0 次**，单局最多也是 0
- 影响：进入编制少了一个 ×2 的正权重项，创业的 ×−1 惩罚项形同不存在
- 设计文档 `docs/talent.md` 提到该标签，`docs/event.md` 的标签表里也有，但**事件从未写上**

### 6.2 「学生组织」标签的天花板只有 3

- 带该标签的事件 18 条，但其中 16 条是加入组织事件（`flags_forbid: 组织`，每局只能触发一次）
- 实测单局均值 1.09、最大 3
- 影响：援建乡村（×2）、创业（×1.5）、进入编制（×2）三条结局的标签项被封顶在 +4.5 ~ +6

- **门槛 v1**：`保研外校 / 保研本校` 共用「保研 ≥ 1 且 智力 ≥ 8」，`考研外校 / 考研本校` 共用「图书馆 ≥ 2 且 智力 ≥ 6」→ 由于 §3.1 的支配关系，**本校两条仍然是 0%**
- **门槛 v2**：把校/外校改成互斥的属性区间（保研外校 智力 ≥ 8 / 保研本校 6 ≤ 智力 < 8；考研外校 智力 ≥ 6 且无保研 / 考研本校 智力 < 6 且无保研），命中种类升到 **8 种**
- 两种门槛下都仍有 **援建乡村 = 0%**（受 §6.2 的标签上限所困）；**延毕 = 0%** 是结构性的：待业（无门槛兜底）得分恒 ≥ 延毕，只要待业在候选里，延毕就永远选不上
- 门槛把「结局由属性决定」改成「结局由经历决定」的效果很明显：出国留学 + 保研外校的合计占比 100% → **36.9%（v1）/ 36.9%（v2）**


## 8. 结论与建议

1. **命中集中的根因是权重表结构，不是随机性**：11 条结局里 5 条被代数恒等式锁死（保研本校、考研本校、待业、延毕、援建乡村），3 条标签供给被封顶（进入大厂、创业、进入编制），剩下 2 条吃满属性增长，同分概率仅 0.2%
2. **`require` 硬门槛是唯一有效手段**：实测能把命中种类从 2 种提到 6 ~ 8 种；但门槛必须**让校/外校互斥**，否则支配关系会让本校两条继续挂零
3. **先补两个数据缺口**，否则任何门槛都救不了这两条：
   - 给「进编制」标签补事件（考公、选调、事业单位实习等），否则进入编制/创业的权重项恒为 0（§6.1）
   - 放宽「学生组织」的标签来源（如把组织内的事件也打上该标签），否则援建乡村/创业/进入编制的标签项被封顶（§6.2）
4. **延毕需要独立的机制**：它被兜底结局「待业」恒久压制（`待业 − 延毕 = 1.5×智力 + 0.5×体质 ≥ 0`），只要待业无门槛可选，延毕就不可能命中 —— 要么给延毕单独的门槛并把待业改成更严的兜底，要么把延毕改成事件触发（挂科/学分不足）
5. **建议实施顺序**：① 补 §6 的两处标签供给（数据层，风险低）→ ② 加 `require` 门槛 v2（门槛互斥）→ ③ 复测命中分布，再决定是否拆分 `attr_weights` / `tag_weights`

> 本文的 v1 / v2 门槛均为**分析用假设**，未写入 `data/endings.json`，也未改动 `game/`；是否实施、按哪种松紧，由人类定夺。
